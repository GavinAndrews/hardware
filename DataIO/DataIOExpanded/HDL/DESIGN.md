# Data I/O 29B Memory Board — Design Summary

## Overview

A bank-switched SRAM expansion board for the Motorola 6802 processor.
Two AS6C4008 SRAM chips provide 512 KB each, giving up to 1 MB of
expanded RAM. Bank selection and address decoding are handled by an
ATF1504AS CPLD.

---

## Hardware

| Component | Device | Notes |
|-----------|--------|-------|
| CPLD | Atmel ATF1504AS TQFP-44 | Address decode, bank register |
| SRAM 0 | Alliance AS6C4008 | 512K x 8, selected by nRAM_A |
| SRAM 1 | Alliance AS6C4008 | 512K x 8, selected by nRAM_B |

---

## CPU Interface Signals

| Signal | Direction | Description |
|--------|-----------|-------------|
| A0–A15 | In | CPU address bus |
| D0–D4, D6–D7 | Bidir | CPU data bus (D5 not connected) |
| nEN | In | Board enable, active low |
| nWR | In | R/W line from 6802, active low = write |
| nVO2 | In | NAND(VMA, E) — active low during valid memory cycle |
| SEL0, SEL1 | In | Memory size jumpers (pull-up, open = 1) |
| TDI, TMS, TCK, TDO | In/Out | JTAG (TDO high-Z during normal operation) |

---

## nVO2 and the 6802 Bus Cycle

The 6802 generates two signals that together define a valid memory cycle:

- **E** (pin 37) — Phase 2 clock, 2 MHz. Low in the first half of the
  cycle while the CPU is settling the address bus; high in the second
  half when address and data are valid.
- **VMA** (pin 5) — Valid Memory Address. Asserted when the current
  cycle is a real memory access (not an internal CPU operation).

The board combines these through a NAND gate:

```
nVO2 = NAND(VMA, E) = NOT(AND(VMA, E))
```

| E | VMA | nVO2 | Meaning |
|---|-----|------|---------|
| 0 | x | 1 | Address settling — no access |
| 1 | 0 | 1 | Internal CPU cycle — no access |
| 1 | 1 | **0** | **Valid memory cycle — access allowed** |

All CPLD enables are gated on `!nVO2`.

### Read cycle timing

```
E:     ____╔══════════╗____
nVO2:  ════╝          ╚════   low = valid window (250 ns at 2 MHz)
A:     ────┤ stable   ├────
R/W:   ════╪══════════╪════   high
nEN:   ════╝          ╚════
nRAM_A:════╝          ╚════   SRAM selected
Data:       [===valid==]       SRAM drives bus; CPU samples near end
```

### Write cycle timing

```
E:     ____╔══════════╗____
nVO2:  ════╝          ╚════
A:     ────┤ stable   ├────
R/W:   ════╪══════════╪════   low
nEN:   ════╝          ╚════
nRAM_A:════╝          ╚════   SRAM selected
nRAM_WE:═══╝          ╚════   = nWR direct
Data:  ════╪══════════╪════   CPU drives bus throughout
                       ↑ posedge nVO2: bank register latches
```

The bank register latches on **posedge nVO2** (falling edge of E). The
6802 guarantees data is held valid past the falling edge of E, making
this a safe capture point. The SRAM write ends when CE# (= nRAM_A) goes
high at the same edge.

## Address Map

| Address | Access | Function |
|---------|--------|----------|
| $2000–$5FFF | R/W | 16 KB RAM window (bank switched) |
| $E300 | Write | Bank register low byte (D3–D0 → bank bits 3–0) |
| $E301 | Write | Bank register high byte (D7 → bit 5 / SRAM select, D6 → bit 4) |
| $E302 | Read | Parity status (D7=0 no error, D7=1 error) |

---

## Bank Register

The 6-bit bank register (`bank_reg[5:0]`) is written in two bytes:

| Write | Data bits used | Bank register bits | SRAM address lines |
|-------|---------------|-------------------|-------------------|
| $E300 | D3, D2, D1, D0 | bits 3–0 | A17, A16, A15, A14 |
| $E301 | D7, D6 | bits 5–4 | SRAM select, A18 |

**bit 5 (D7 of $E301):** selects which SRAM chip is active:
- 0 → SRAM0 (nRAM_A asserted)
- 1 → SRAM1 (nRAM_B asserted)

**bits 4–0:** drive SRAM address lines A18–A14 (RB4–RB0), selecting
which 16 KB bank within the chosen chip is mapped to $2000–$5FFF.

---

## Address Routing

The CPLD does not buffer the CPU address lines — they connect to the
SRAMs directly:

```
CPU A13–A0  ──────────────────────────────► SRAM A13–A0  (14 bits, direct)
bank_reg[4:0] ── RB4–RB0 (CPLD outputs) ──► SRAM A18–A14 (5 bits, bank select)
```

A13 is routed directly from the CPU rather than generated by the CPLD,
providing 8 KB granularity within the 16 KB window without consuming a
CPLD macrocell.

---

## Memory Size Limiting

Jumpers SEL0 and SEL1 cap the maximum accessible bank number, preventing
software from writing to non-existent memory beyond the installed
capacity:

| SEL1 | SEL0 | Max bank | Capacity |
|------|------|----------|----------|
| 0 | 0 | 31 | 1 MB (both SRAMs fully used) |
| 0 | 1 | 15 | 512 KB |
| 1 | 0 | 7 | 256 KB |
| 1 | 1 | 3 | 128 KB |

Jumpers are pull-up: open = 1, fitted = 0.

If `bank_reg[4:0]` exceeds `max_bank`, both nRAM_A and nRAM_B remain
high (no SRAM selected) for that cycle.

**AS6C4008 model notes:**
- Read is fully combinatorial (`DQ = mem[A]` while CE#=0, OE#=0, WE#=1)
- Write is level-sensitive (data captured continuously while CE#=0, WE#=0)
- Initialised to 0xFF on startup
